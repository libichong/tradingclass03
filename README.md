# 逐流 · 市场数据工作台

Flask + HTML5 的本地市场数据工作台，包含只读数据浏览、研究型模拟撮合实验室和日内因子回测。不连接实盘，不向交易所下单，也不修改 Parquet 文件。

## 启动

Python 3.10 或更高版本，在项目目录执行：

```powershell
python -m pip install -r requirements.txt
python main.py
```

浏览器打开 http://127.0.0.1:5000 。默认仅监听本机，关闭调试模式。
请确保安装依赖和启动使用同一个 Python 环境。当前 VS Code 环境也可直接执行：

```powershell
& 'C:\app\anaconda3\envs\TicketBuddy\python.exe' main.py
```

## 数据与展示

- 从项目自身的 `Data` 目录读取文件，不依赖启动时的工作目录。
- 支持名称以 `exe`（逐笔成交）、`snp`（行情快照）、`ord`（逐笔委托）开头的 `.parquet` 文件；不递归子目录，不读取符号链接。
- 自动发现文件并统计行数、字段和大小。新增或替换文件后点击“刷新文件”。
- 以 DuckDB 按需查询，不将整份文件导入 Python / 浏览器。每次响应最多 500 行。
- 支持文件选择、六位证券代码、毫秒级起止时间（含边界）、分页与页码跳转。
- 默认按文件原始行序展示，不视为跨通道的交易所事件排序。
- 默认展示常用字段，可切换全部字段；每条记录都有原始字段详情，快照额外展示十档盘口。
- 当前数据的 `Symbol` 为整数，界面补齐六位；`Time` 按 `HHMMSSsss` 解读，如 `92500000` 显示为 `09:25:00.000`。时间筛选依赖此源格式。
- 表格价格最多显示六位小数以减少 FLOAT 尾差；鼠标悬停和记录详情保留读取后的原始数值，不修改源文件。
- 枚举不擅自翻译：`BSFlag`、`FunctionCode`、`OrderKind` 等显示原始代码。数量、金额不换算单位，需后续结合供应商数据字典确认。
- JSON 中超过 JavaScript 安全整数范围的整数使用字符串，非有限浮点数表示为 `null`。
- 缺失目录、损坏文件或查询失败会显示错误，详细异常记录在服务端日志。

## 接口

- `GET /api/files`：返回 `files`，包含名称、类型、文件名中的日期、字节大小、总行数、字段描述。
- `GET /api/data?file=exe_20260923.parquet&page=1&page_size=100&symbol=601688&start=09:30:00.000&end=15:00:00.000`
  - `file` 必填；`symbol`、`start`、`end` 可省略。
  - 返回 `file`、`columns`、`rows`、`total`、`page`、`page_size`、`pages`。
  - 页大小 1–500；超出结果范围的页码归到最后一页；零结果返回空数组和第 1 页。
  - 参数错误返回 JSON / HTTP 400，文件读取失败返回 JSON / HTTP 503。

## 撮合实验室

打开 http://127.0.0.1:5000/replay ，也可从原始数据页右上角进入。

1. 选择 `ord` 文件、单个六位证券代码及时间区间，确认字段映射和模型边界后加载。默认 `601688 / 09:30–10:00`。也可主动选择“内置演示”，使用六笔示例，不与真实数据混淆。
2. 点击“下一事件”逐笔推进，或用 0.5 / 1 / 5 / 10 / 50 / 100 倍速连续回放。时间进度按模拟时钟而非每帧固定笔数推进；同一时刻多笔事件保持确定性顺序。
3. 在暂停或运行时注入买 / 卖限价单：
   - **单笔限价**：延迟为 0 时在当前模拟时钟提交；延迟为正则入队，随回放推进。
   - **定时拆单**：按指定模拟毫秒间隔释放子单，最后一单取剩余量；计划不能超出回放区间。
   - **冰山补单**：只挂展示量，当前子单全部成交后补下一单。补单是新的独立事件，失去原排队优先级，隐藏量不进入盘口。这是研究型执行策略，不是交易所原生冰山规则。
4. 查看十档模拟盘口、逐笔成交和买卖双方生命周期。成交详情保留双方申报时间、原始总量及该笔成交后余量。模拟单用 `S:` 标识，计划用 `P:`，历史单用 `H:通道:原始号`，无 ID 段碰撞。
5. 撤销模拟子单时会停止其所属整个计划，同时撤掉所有尚存挂单与未提交子单。历史撤减由事件队列驱动。重置创建新的空簿实验，不影响其他标签页。

### 适配与模型边界

- 经用户确认的研究映射：`FunctionCode=66/83` 表示买/卖；`OrderKind=65/68` 表示新增/按 `Volume` 撤减；用 `Channel + OrderOriNo` 关联订单。`OrderKind=83` 只显示原始阶段码，不触发竞价规则。该映射不是供应商协议认证。
- 读取单证券区间，按 `Time, BizIndex, Channel, file_row_number` 排序。载入时校验字段、事件编码和重复新增标识；未知编码明确拒绝，不静默跳过。
- 该证券区间内的事件会完整载入进程内存用于队列调度，长区间需要更多内存；原始三类数据浏览仍按页查询。
- 全部历史事件和模拟事件进入同一优先队列，按模拟毫秒与递增序号排序。同时间戳先处理已入队历史事件，再处理后来注入的模拟单；同价 FIFO 以实际入引擎顺序为准。
- 从选定区间的**空订单簿**开始，不预热、不复原真实盘口、不使用成交或快照文件校准。所有新增均作为普通限价单，成交价取被动单价格；不实现集合竞价、市价单、价格笼子、涨跌停、自成交限制或交易所特有规则。
- 价格在引擎内以整数分表示；历史 FLOAT32 价格恢复到 0.01 价位，无法落入此模型的价格会拒绝。模拟价格必须为 0.01 的整数倍。单笔总量支持 1–1,000,000,000，价格支持 0.01–10,000,000。
- 注入会改变模拟订单簿，但后续历史订单仍为固定输入，并不模拟市场参与者反应。因此不能把结果解释为真实冲击预测或可实现收益。
- 切片前订单缺失、模拟成交提前耗尽挂单等可能造成历史撤减目标缺失。此类事件明确显示警告并计数；撤减超出当前剩余量时仅撤剩余量并警告。价格与数量守恒仍成立。
- 三类事件/成交流及每侧生命周期仅展示最近 200 条（单）；累计计数不截断。完整订单状态在会话内保留。不是持久化审计或回测报告系统。

### 回放运行与接口

- 每个页面持有独立随机会话令牌，以 `X-Replay-Session` 请求头传递。服务端会话加锁，序列化回放/注入/撤销，避免同一会话并发破坏队列。页面请求也串行，不使用可能重叠的 `setInterval`。
- REST 拉取驱动：页面运行时每次请求完成后约 150ms 触发下一次 `/tick`；后端用单调时钟计算目标模拟时间，单请求最多处理 1000 事件，积压时继续处理而不丢事件、不越过未消费事件。
- 页面不请求时不会在后台自动撮合；恢复请求时按时钟推进积压。暂停保留当前已消费进度。网络异常停止自动轮询，不自动重试注入；界面提示状态需确认。
- 会话状态仅存在当前 Python 进程内；闲置 30 分钟后，在后续会话访问/创建时清理。刷新页面或重启服务后需要重新加载。仅用于单进程本地实验，不支持多进程共享或登录权限控制。
- `POST /api/replay/session`：`file, symbol, start, end, mapping_confirmed` 创建/替换本页面会话；返回 `session_id` 及状态。
- `GET /api/replay/state`：只读当前状态；`POST /api/replay/tick`：推进到当前虚拟时间。
- `POST /api/replay/control`：`action=play/pause/step`，`play` 可带 `speed`。
- `POST /api/replay/orders`：`side, price, volume, mode=single/split/iceberg, delay_ms`；自动模式再传 `clip`，拆单再传 `interval_ms`。
- `POST /api/replay/cancel`：`id`，撤销模拟订单/计划；`DELETE /api/replay/session` 释放本会话。
- 响应携带十档盘口、最近事件、成交与生命周期窗口和版本号；前端根据版本高亮本轮增量变化。不是 SSE 推送协议。

## 因子研究与日内回测

访问 http://127.0.0.1:5000/backtest 。选择交易日、回看窗口（5–60 分钟）、持有期（1–30 分钟）、分组数及费用后，一次计算图片所列的十个因子。结果包含策略/等权基准/50–50 多空净值、分组收益、持有期端点最大回撤、期频夏普、参考年化夏普、胜率、Rank IC、逐期信号及最近一期截面。

悬停或键盘聚焦总览表、公式列表中的因子名称，或当前因子选择框，可查看含义、数值解读、计算口径与生效条件。按 Esc 关闭说明；点击总览名称仍会切换图表。

### 因子相关性与交易特征

因子页新增同一时点的 **10×10 截面 Pearson / Spearman 热力图**、绝对相关最高的五组因子对和逐股票交易特征表。

- 默认从尾盘向前寻找十因子共同有效股票不少于 3 只的最近完整分钟。也可选择其他分钟；若没有合格时点，明确显示样本不足，不改用其他口径。
- 信号截止为所选分钟的 `:59.999`。所有矩阵格子使用十因子均有有限值的同一股票交集（listwise），不逐对删样本，不混合不同时点，也不使用后续收益。
- 同时显示股票池数量、共同样本数、排除数和单因子有效数。单因子有效数不等于矩阵 N；交易特征表可查看全部股票及其排除原因，或仅显示共同样本。
- Pearson 衡量线性关系；Spearman 对同值使用平均秩。共同样本不足 3 只或某列为常数/数值方差过小时，相关系数显示“—”，对角线也不强制填 1。相关不代表因果，也不自动构成剔除因子的依据。
- 时间选择与回测持有期独立，允许分析 14:56 这种没有后续完整持有期的分钟。切换分析时点只刷新相关性和交易特征，不改变已计算的回测收益；使用最近一次成功回测的日期、窗口及大单阈值。

交易特征包括 **最新价、窗口复利收益、分钟收益波动率、成交量、成交额、成交笔数、平均单笔成交金额、主动买额占比、主动买卖失衡、大单净买额及占比、新增委托失衡、买卖价差、相对价差 bps、一档深度失衡**。页面表头悬停和“交易特征计算口径”提供逐项定义：

- 流量类取最近 L 个交易分钟，可以跨午休累计；收益/波动要求 L 个连续分钟收益，午休后需重新积累完整窗口。
- 价差为信号分钟最后一条有效价格快照的 `AskPrice1−BidPrice1`，相对价差除以同一快照买卖中间价再乘 10000。
- 一档深度失衡为同一快照 `(BidVolume1−AskVolume1)/(BidVolume1+AskVolume1)`。
- 报价字段可选，不影响原回测兼容性；缺失、非有限、零报价或交叉盘口时不计算价差/深度，不向前回填报价。负盘口量或总量为零时深度无定义。缺失特征显示“—”，不是 0。
- 成交金额/量保留源单位，大单阈值和成交方向沿用已确认的研究口径；“净买额”不是账户级资金实际流入。
- `GET /api/backtest/catalog` 额外返回可选完整分钟；`POST /api/backtest/run` 自动附带默认 `analysis`；`POST /api/backtest/analysis` 接受同样的日期/窗口/大单阈值参数及可选 `minute="HH:MM"`，独立返回截面分析。未传 `minute` 或传 `null` 使用自动时点。

### 公开代理公式（不是研报复现）

`r` 为快照最新价的一分钟收盘收益，`L` 为回看窗口；`A` 为成交额，`B/S` 为主动买/卖额，`LB/LS` 为大单主动买/卖额，`OB/OS` 为新增买/卖委托额。金额均为 `Price×Volume`，未核验供应商单位。

| 图片因子 | 本项目代理公式 |
|---|---|
| 高频偏度 | 最近 L 个分钟收益率的校正样本偏度 |
| 下行波动占比 | `Σ min(r,0)² / Σ r²` |
| 开盘后买入意愿占比 | 开盘 30 分钟 `OB / (OB+OS)` |
| 开盘后买入意愿强度 | 开盘 30 分钟 `(OB−OS) / A` |
| 开盘后大单净买入占比 | 开盘 30 分钟 `(LB−LS) / A` |
| 开盘后大单净买入强度 | 开盘 30 分钟 `(LB−LS) / (LB+LS)` |
| 改进反转 | 最近 L 分钟 `−Σr × (1−abs(B−S)/A)` |
| 尾盘成交占比 | 14:30 至当前成交量 / 09:30 至当前成交量，**不使用未来全日成交量** |
| 平均单笔流出金额占比 | 最近 L 分钟平均主动卖额 /（平均主动买额 + 平均主动卖额） |
| 大单推动涨幅 | 最近 L 分钟 `Σ[r_m × (LB_m−LS_m) / A_m]`，无成交分钟贡献 0 |

- 已由用户确认用于研究：成交 `BSFlag=66/83/0` 表示主动买/卖/未知，未知仍计总额但不计方向净额；委托只取 `OrderKind=65`，`FunctionCode=66/83` 表示买/卖。
- 默认大单阈值为单笔成交额 200,000，可调整；不是母单级别的大单识别。
- 开盘因子完整使用 09:30–10:00，10:00 才能用于建仓；尾盘因子最早 14:31 可用，实际建仓还受持有期网格约束。
- 只研究 09:30–11:30、13:00–14:57，不跨午休持仓，不使用收盘集合竞价；分钟收益不跨午休计算。依赖收益率的滚动因子午后重新积累 L 分钟；纯成交均额因子按交易分钟回看。
- 分母为零、零收益方差或窗口缺失时返回无定义，不伪造因子 0。不同因子取值不足分组数时该期不交易；同值按证券代码稳定排序，并报告存在同值的期数。

### 时序、组合与指标

信号使用建仓前一分钟及更早的信息，建仓/平仓价取对应分钟**第一条有效快照最新价代理**。先确定分组再读取后续收益，未来成交价格缺失直接报错，不用未来可用性筛选证券。股票池为当日文件内固定样本，不是全市场。

每期各组内等权，全额开平仓，再进入下一期；不是只扣净额换仓成本。因此高频往返费用可能主导收益。没有完整后续持有区间的尾段不交易。可做多最高组或最低组，不按本次收益自动优化方向。

令 `c=(单边手续费bps+单边滑点bps)/10000`：

- 多头每期扣费收益：`(1+毛收益)×(1−c)/(1+c)−1`，各期复利。
- 基准为同一期全部有效证券等权，扣相同双边费用；累计相对收益为 `策略净值/基准净值−1`。
- 多空使用 50% 多头、50% 空头（总敞口 1），每期净收益 `0.5×(r_long−r_short)−c×[2+0.5×(r_long+r_short)]`，没有借券成本。
- 最大回撤：`max(1−净值/此前峰值)`，含初始净值 1；**仅在持有期端点采样，不能视为期间内最大回撤**。
- 期频夏普：期收益均值 / 样本标准差，无风险利率为 0；不足两期或零方差时不显示数值。
- 参考年化夏普：期频夏普乘 `sqrt(252×237/持有分钟)`。这是单日机械外推，不具统计可靠性，不展示虚假可靠的年化收益率。
- Rank IC 为当期因子值与后续持有期毛收益的 Spearman 相关（同值取平均秩），并非训练或择优信号。

| 大单推动涨幅 | 36 | -0.776% | -4.285% | -0.472% | -0.033 |

- **十个最高组的扣费累计收益均为负。** 部分因子相对基准为正，只表示在同口径下“少亏一些”，不能写成策略已盈利。50–50 多空扣费累计收益也全部为负，约为 **-0.398% 至 -4.181%**；当前设置没有展示出覆盖费用后的正收益。
- **不能把尾盘因子的 -0.517% 当作全日最优。** 它只有 4 期，建仓从 14:35 开始；开盘因子从 10:00 开始有 39 期，收益滚动因子从 09:55 开始有 36 期，平均单笔流出因子从 09:50 开始有 41 期，均在 14:55 完成最后一次平仓。暴露时长、市场阶段、累计扣费次数不同。
- 即使有效期数相同，因子可用股票也不一定相同。例如 36 期因子的基准累计收益约为 **-3.831%**，39 期约为 **-4.212%**，41 期约为 **-4.423%**；这些同样是全额往返扣费后的研究基准，不是股票池从开盘买入并持有到收盘的市场涨跌幅。

#### 2. 费用是本次净收益恶化的主要来源

本次单边总成本为 `c=0.0005`。若每期毛收益恰为 0，单次往返净收益为 `(1−c)/(1+c)−1 ≈ −0.09995%`，约 **10 bps**。连续 N 期的纯费用损耗为：

```text
1 − [(1−0.0005)/(1+0.0005)]^N
```

36、39、41 期分别约损耗 **3.54%、3.82%、4.02%**。更准确地说，当前模型中同一组的净值等于毛净值乘以上述 N 期费用因子；不能把毛收益与净收益之差一概当作简单累加手续费。

下行波动占比、两项开盘买入意愿的毛累计收益仅约 **+0.065% / +0.082%**，远小于多次全额开平仓损耗。因此，本次结论是“在当前持有期和成本假设下，信号收益不足以覆盖费用”，而不是“只要降低费用就一定能盈利”。零费结果仍未计冲击、成交约束及借券成本。

尤其是开盘因子在 10:00 后取固定开盘窗口值，信号排序不随后续分钟更新，却仍按每 5 分钟全额开平仓扣费。这一设定用于统一研究口径，不等价于持有同一篮子不交易，也不等价于只按实际换仓扣费。后续若研究执行效率，应另行设计持仓延续与净额换仓模型，并明确区分新旧口径。

#### 3. 分组收益与 IC：观察排序能力，不只看最高组

- **开盘后买入意愿占比**的 G1→G5 扣费累计收益依次约为 **-4.611%、-4.294%、-4.258%、-4.153%、-3.746%**，本日呈单调改善。结合平均 IC **+0.042**，可以把它列为后续多日检验的候选，但仍不能称为显著有效。
- **下行波动占比**的最高组优于最低组（**-3.473% 对 -4.355%**），但中间组并不严格单调；**改进反转**最高组也不是五组中最好的组。这提醒我们，端点组收益差与整个截面的稳定排序能力不是同一件事。
- **大单推动涨幅**本次平均 IC 为 **-0.033**，最高组相对基准为 **-0.472%**；36 个有效期中 **12 期存在同值**。同值时证券代码参与稳定分组，组间差异可能受这一规则影响，应检查同值比例、成员及大单阈值敏感性，而非直接把代码排序结果解释成经济信号。
- **尾盘成交占比**虽然平均 IC 为 **+0.079**，却仅有 4 个 IC 样本，最高组相对收益仍为负。IC 是全截面的秩关系，实际持仓只取一个端点组，还受到收益幅度和费用影响，二者不要求同号。
- 本日平均 IC 约落在 **-0.033 至 +0.079**，尚无显著性检验；相邻期共享回看信息，开盘因子还重复使用同一信号，因此期数不能直接当作独立样本数。十因子、多窗口、多方向试验也会产生多重比较和事后择优风险。

#### 4. 相关性：识别重复信息，不直接判定收益

默认分析时点为 **14:56（截止 14:56:59.999）**，十因子的共同有效样本为 **50/50 只**，排除数为 **0**。以下均来自同一截面的共同样本，不与回测各期的样本或 IC 混用。

| 因子对 | Pearson | Spearman | 本次可以作出的描述 |
|---|---:|---:|---|
| 开盘后买入意愿占比 / 强度 | +0.940 | +0.982 | 线性与排序关系都很强，存在明显信息重叠 |
| 开盘后大单净买入占比 / 强度 | +0.884 | +0.976 | 排序更接近，分母变化仍影响数值尺度 |
| 高频偏度 / 下行波动占比 | -0.729 | -0.647 | 此截面中分布形态与下行风险方向相反 |
| 下行波动占比 / 改进反转 | +0.707 | +0.712 | 与近期收益路径相关的信息可能重叠 |

这种重叠有公式依据：令 `q=OB/(OB+OS)`，买入意愿强度为 `(2q−1)×(OB+OS)/A`；两项开盘大单因子也共享 `LB−LS` 分子，但分别除以 `A` 与 `LB+LS`。分母若在股票间变化不大，排序容易接近；分母差异较大时，两者仍可提供不同信息。

本次两项开盘买入意愿最高组毛/净收益完全相同，但最低组及部分中间组不同。因此**相关系数接近 1 不等于所有分组或信号完全相同**。组合研究中不宜将高度相关的两项各算一份独立证据；可在多日、多个时点上检验相关稳定性，再研究去冗余或增量预测能力。低相关也不自动代表因子有效，负相关更不是做空依据。

14:56 没有本设置下可用的后续完整持有区间，适合描述截面关系，却不能用来解释当日最后一个已完成持仓的收益。相关矩阵不使用后续收益，也不提供因果检验。

#### 5. 用交易特征解释异常和可交易性

逐股票交易特征表适合核查“为何某只股票因子极端或缺失”，不能替代组合收益检验：

- **成交额、成交笔数与平均单笔金额**结合看：同样的净买占比，来自大量成交还是少量大单，稳定性可能不同；固定 200,000 阈值对不同活跃度证券并非同样严格。
- **主动买额占比、主动买卖失衡、大单净买占比**结合看：区分总体买入占优与少数大单占优；这些是成交方向统计，不是账户资金流入证明。
- **新增委托失衡与实际成交失衡**对照看：委托意愿不等于成交，不扣撤单的新增委托额也不是当前真实盘口存量。
- **相对价差、盘口深度失衡与分钟波动率**用来识别价差较宽、深度不平衡或价格变化较大的证券。分钟末报价只是单个快照，不等于持有期间平均流动性；不能把表中价差直接当作已经模拟的滑点。
- 缺失值和被排除原因应与有效股票数一起报告。本次默认截面共同样本完整，不意味着其他时点、其他回看窗口也完整；不要将“—”改成 0 后再计算相关或排序。

#### 6. 更可靠结论所需的后续验证

以下是研究建议，**当前页面尚未实现自动多日验证、统计检验或组合去相关**：

1. **统一比较区间与股票样本**：滚动因子与开盘因子先在共同可交易时点比较；尾盘因子单列，或只比较相同尾盘区间，避免把少交易当作更优。
2. **拆分信号与成本**：固定成员分别报告毛/净收益、持仓期数与费用损耗，预先设定费用和持有期范围，检查结论是否依赖某个参数点。延长持有期会同时改变收益目标与交易次数，不能只视作减少扣费。
3. **扩展多日并按日期做样本外检验**：预先固定公式、方向和阈值，先在研究日期确定方案，再在未参与选择的日期验证；统计 IC 方向一致性、分组单调性、收益集中度和相关矩阵稳定性。考虑日内依赖后再选择分块重采样或其他适当检验。
4. **检验流动性和数据口径**：核验金额/量单位、方向编码、大单识别和盘口异常；研究容量、成交量参与率、价格限制及执行价格，避免把快照最新价当作无限量成交机会。
5. **区分因子研究与可执行策略**：若目标是 A 股实盘，应先设计符合 T+1、融券及实际换仓约束的持仓方案，再重建回测。当前数字不能直接转化为实盘预期。

**本次总结：费用明显主导扣费表现；开盘买入意愿呈现值得继续检验的分组排序，但与对应强度指标高度重叠；单日、50 只固定股票、少量且相关的日内样本不足以证明稳定超额收益。**

### 关键限制与接口

- 当前只有单日数据，没有样本外验证、显著性检验、跨日预测或深度学习模型。不同因子的有效时段不同，不宜直接拿累计收益排名判断优劣。
- A 股 T+1、融券、成交量约束、盘口冲击、涨跌停可成交性均未实现。这是**日内因子研究组合，不是可执行交易回测**。
- 原始 Parquet 由 DuckDB 聚合到分钟，只缓存最多 4 份分钟面板；缓存键包括路径、修改时间、大小和大单阈值，不修改源文件。
- 文件按 `exe_YYYYMMDD.parquet` / `snp_YYYYMMDD.parquet` / `ord_YYYYMMDD.parquet` 同日配对；缺少任一类型的日期不可运行。
- `GET /api/backtest/catalog` 返回日期覆盖和公式；`POST /api/backtest/run` 接受 `date, window, holding, groups, direction, large_threshold, fee_bps, slippage_bps`，返回十因子结果、曲线、逐期成员、数据质量和限制说明。

这是单机数据查看原型，Flask 自带服务不适合直接对公网部署。尚未增加登录、实时数据流、文件写入期间的一致性保证或后台索引；大型文件深分页及筛选统计可能需要扫描文件。
